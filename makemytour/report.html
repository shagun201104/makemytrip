1. INTRODUCTION & PROJECT OVERVIEW

This project is a full-stack web platform for travel bookings, modeled after MakeMyTrip. The goal was to build a clean, working web application where users can search for flights and hotels, track live flight status updates in real time, view dynamic pricing trends, select specific seats or hotel rooms, and manage cancellations with refund calculations.

The application is built using Next.js 16 (App Router) with TypeScript and Tailwind CSS. The state management is handled using React hooks and browser local storage for persistence across page reloads.

1.1 Key Objectives

  1. Implement a search system for flights and hotels with input validation.
  2. Build a live flight tracking engine that simulates status changes (On Time, Boarding, Delayed, Landed) based on actual time.
  3. Develop a dynamic pricing module that adjusts base prices according to peak travel periods and weekend demand, supported by visual price history charts.
  4. Design interactive seat and room selection grids for booking customization.
  5. Create a self-service cancellation dialog that calculates refund amounts based on cancellation timing.
  6. Ensure full mobile responsiveness across all devices, including iOS and Android browsers.

2. SYSTEM DESIGN & ARCHITECTURE

3. IMPLEMENTATION DETAILS BY MODULE

3.1 Flight & Hotel Search Engine (app/page.tsx)

The homepage contains a dual-tab search card for flights and hotels. Users can select departure/destination cities, departure date, and number of passengers using steppers (+ and - controls).

  • Input Validation: Ensures departure and destination cities are not identical and mandatory fields are filled before submitting.
  • Mobile Layout Fix: Date inputs on mobile WebKit (iOS Safari) were originally overflowing container boundaries. This was resolved by wrapping <input type="date"> elements inside a wrapper div styled with overflow-hidden border-2 border-[#cbd5e1] rounded-2xl min-w-0 w-full.

3.2 Live Flight Status Tracking (app/flight-status/page.tsx & lib/flightStatusApi.ts)

The flight tracking page simulates live status changes for active flights.

  • Time Calibration: The engine was adjusted to run at a 1:1 real-time scale (1 second = 1 second of flight time) so flights progress in real time rather than sped-up simulation.
  • Status Updates: Flights move through states (ON TIME → BOARDING → IN FLIGHT → LANDED or DELAYED).
  • Context & Management: If a flight is delayed, a reason is generated (e.g., weather conditions). Users can add custom flight numbers to track, or remove flights using the delete button, which immediately updates state and local storage (mmt_tracked_flights).

3.3 Dynamic Pricing Engine (components/LivePrice.tsx & PriceHistoryChart.tsx)

Base prices automatically recalculate based on demand metrics: 1. Peak Season Multiplier: Fares increase by 20% during holiday dates. 2. Weekend Surge: Fares increase by 10% on Friday through Sunday departures. 3. Price History Graph: A line chart built with Recharts shows 7-day price trends, helping users decide when to book.

3.4 Interactive Seat & Room Selection

  • Flight Seat Map (InteractiveSeatMap.tsx): Displays an airplane layout divided into Business and Economy sections. Occupied seats are disabled, while available seats display price add-ons.
  • Hotel Room Grid (InteractiveRoomGrid.tsx): Displays available room types (Deluxe, Suite, Villa) with occupancy limits and amenity tags.

3.5 Cancellation & Refund Handling (CancellationDialog.tsx)

Allows users to cancel existing bookings and view a breakdown of their refund: * Cancellation > 24 hours before trip: 100% refund (minus standard transaction fee). * Cancellation ≤ 24 hours before trip: 80% refund.

3.6 Admin Panel (app/admin/page.tsx)

A dashboard styled with a dark navy background (#0f172a) to manage platform stats, monitor active flights, check hotel inventory, and view total revenue figures.

4. CHALLENGES & RESOLUTIONS

Problem Encountered Technical Root Cause Resolution Applied
Date input overflow on mobile iOS Safari renders native <input type="date"> WebKit controls with fixed intrinsic width, causing them to push outside parent card borders. Wrapped input in a container <div className="w-full min-w-0 overflow-hidden rounded-2xl border-2 border-[#cbd5e1] bg-white"> with appearance-none on the input element.
Fast simulation speed Flight status was updating every few seconds, making tracking feel unrealistic. Recalibrated timer ticks in flightStatusApi.ts to 1:1 real-time scale.
Deleted flights re-appearing State was updating locally but not syncing with localStorage. Updated deletion function to write the updated array back to localStorage.setItem('mmt_tracked_flights', ...) immediately.
Search button color mismatch Search buttons used different shades of blue and orange across pages. Unified all search action buttons to #215190 (Steel Sapphire Navy) with 44px height.
